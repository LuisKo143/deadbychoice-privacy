Privacy Policy

Dead by Choice Automation · Last updated: 24 October 2026

Service status: technical setup and testing. The application is being configured for the audience-voting process described below. Public automated voting has not yet started. Test API requests and their execution logs are covered by this policy.

1. Who is responsible?

Luis Kollnig operates Dead by Choice Automation for the Instagram account @deadbychoice.series in Austria. For privacy questions or deletion requests, contact luis.kollnig@gmail.com.

2. What the application does

The application reads comments on this account's own Instagram posts to count audience votes, such as A or B, and determine how a fictional story continues. The account owner reviews and manually uploads the resulting videos.

The planned workflow does not automatically publish posts, send direct messages, reply to comments, hide comments or delete comments. A technical permission may enable additional actions, but they are not part of this workflow.

3. Data and sources

Data is obtained through Meta's official Instagram API for the connected professional account. Depending on the API response and enabled workflow steps, it includes:

  • Account ID and username of the connected account.
  • Post IDs, captions, publication times and links.
  • Comment IDs, text, publication times and, when available, the author's account ID or username.
  • Vote totals, winning options, cut-off times and technical job identifiers.
  • Technical execution logs needed to diagnose failed requests.

Access tokens are stored as credentials in the self-hosted n8n installation. The application does not request commenters' Instagram passwords.

4. Purposes and legal basis

Processing for operation and technical testing is based on legitimate interests under Article 6(1)(f) GDPR: running a voluntary audience vote on the operator's own posts, maintaining story continuity, preventing duplicate votes where supported, and diagnosing technical failures. Processing is limited to these purposes; commenters may object as explained below.

Voting is voluntary. You can watch the stories without submitting a vote. There is no statutory or contractual requirement to provide a voting comment.

Automatic vote counting affects a fictional story. It is not intended to make decisions about a person with legal or similarly significant effects, or to profile commenters.

5. Processing and recipients

Comment retrieval and vote counting run in a self-hosted n8n installation on the operator's Debian server. Execution logs can contain API responses, including comment data, and must follow the retention rules below.

The workflow is designed to pass only aggregate vote results, technical job information and fictional story context to the private GitHub project and OpenAI's ChatGPT/Codex cloud. Individual comments, commenter names, commenter IDs and access tokens are excluded from that handoff. During setup, the operator checks this data boundary before enabling automated audience voting.

Meta provides the Instagram account and API. GitHub hosts this public policy page and the private technical handoff repository. OpenAI provides cloud story generation and rendering. GitHub and OpenAI do not receive raw audience comment data through the planned handoff. Provider processing, including website access information, is subject to the respective privacy information. GitHub and Meta may process service data internationally, including in the United States; their privacy information explains applicable transfer arrangements. Links are provided below.

Comment data is not intended to be sold or used for advertising profiles.

6. Retention

The current self-hosted n8n installation uses its default execution-data settings. Successful, failed and manual executions can be saved, including the API responses they contain. Automatic pruning is enabled by default: completed executions become eligible for deletion after 336 hours (14 days), or earlier when the execution-count limit is reached. Deletion runs periodically, so 14 days is a pruning threshold rather than an exact deletion deadline.

Unfinished or waiting executions and annotated executions can be excluded from automatic pruning. Such records are retained for the ongoing run or the troubleshooting purpose for which they are kept, rather than as a separate voting archive. They require manual review and deletion when that purpose ends. The current setup has no automatic server or n8n backups or snapshots. This description will be updated if backup storage is introduced.

No separate archive of raw voting comments is part of the planned workflow. Credentials remain stored while the connection is needed and are removed when it is discontinued. Privacy-related correspondence is retained while necessary to handle the request and any resulting obligations or dispute.

Aggregate story outcomes may be kept for continuity, provided they do not contain identifiers or information that singles out an individual voter. The original Instagram comments remain subject to the account holder's and Meta's controls; deleting local copies does not delete the original comment on Instagram.

7. Your rights and deletion requests

Subject to the GDPR's applicable conditions, you may request access, correction, erasure or restriction of processing. You may object to processing based on legitimate interests. Data portability applies where its legal conditions are met.

To request deletion of copies held by this application, email luis.kollnig@gmail.com with the subject “Dead by Choice — data deletion”. Include your Instagram username and the relevant post link or comment details so the data can be located. Do not send your password or an access token.

Deleting your comment on Instagram may not remove a copy already held in an execution log. Contact the operator if you also want local copies removed. Removal of a local copy does not necessarily reverse a previously completed aggregate story vote.

You may lodge a complaint with a supervisory authority, including the Austrian Data Protection Authority.

Instagram's separate processing is described in Meta's Privacy Policy.
